# Communication Matrix

Status: live operator matrix / pseudonymized / non-public by default

This matrix translates live communication situations into sovereignty-preserving moves.

It is not a script library for manipulation. It is a discipline surface for keeping THE TRANSLATOR's help useful without becoming corrective, managerial, or deflating.

---

## Matrix Rule

Every communication move should answer six questions:

1. What is the situation?
2. What is the sovereignty signal?
3. What response would collapse the exchange?
4. What gesture preserves capacity?
5. Which control room is being opened?
6. What phrase can be used without sounding like instruction?

## Phrase Bank

Use these as fragments, not scripts.

- "That direction has force."
- "Zero-point first."
- "The old thing can be material without becoming the origin."
- "This is a good challenge-object."
- "The question is what kind of machine it wants to be."
- "We can test the value before building the whole arena."
- "That gives the later build more ammunition."
- "This is not about reducing the idea. It is about giving it a sharper proof surface."
- "The existing platform can be a laboratory, not a limitation."
- "The app should be built with evidence, not just pressure."

---

## Sequence Template

When a live idea emerges:

1. **Name the force** — what is attractive about the idea?
2. **Classify the mechanism** — judgment, publishing, market, matching, community, archive, game, proof.
3. **Find the reality surface** — where can this be tested without building the entire infrastructure first?
4. **Preserve the later build** — make testing feel like ammunition for THE ARCHITECT's eventual build.
5. **Invite selection** — let THE ARCHITECT choose which room to enter.

---

## Primary Discipline

THE TRANSLATOR's live task is to convert "there is more to know" into:

> "this idea is now large enough to open another control room."

The receiver should never be asked to admit deficiency before entering the room.
