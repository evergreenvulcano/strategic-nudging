# Language Rules

The core constraint of this framework: **language is never corrective. It is always capacity-expanding.**

These rules apply to all documents, all deliverables, and all communications produced within this framework.

---

## The Fundamental Rule

> The language must never position the receiver as deficient. It must always position them as someone whose capacity now opens onto new territory.

Not: *"You don't understand X."*  
But: *"What you've built has now passed the level where build-capacity alone is sufficient. The next knowledge layer is what allows your build-capacity to reach full effect."*

---

## Prohibited Language Patterns

These patterns are not allowed in any framework deliverable:

| Prohibited | Replace With |
|-----------|-------------|
| "You're missing X" | "X is the next territory your scale demands" |
| "You need to learn X" | "X is the next control room to unlock" |
| "This is a problem" | "This is the next proof level" |
| "This is a risk" | "This is an unguarded surface" |
| "You don't know business" | "Business is the control room for survival" |
| "Your projects are too many" | "Value is currently submerged in unresolved breadth" |
| "You're doing it wrong" | (never used — reframe entirely) |
| "Audit", "gap analysis", "red flags" | "Expansion map", "next surfaces", "unlit rooms" |
| "Playbook" (as first delivery) | "Expansion map", "dossier", "territory map" |

---

## Required Language Posture

1. **Begin with proof.** Every document acknowledges what has already been demonstrated before introducing what comes next.

2. **Name the territory, not the lack.** Gaps become rooms. Rooms are not shameful. Rooms are spaces the empire has not yet entered.

3. **Scale explains requirements.** The reason new domains are needed is never that the builder is insufficient — it is that the thing being built is large enough to require them.

4. **Sovereignty is non-negotiable.** The receiver's identity as a builder, creator, and operator is never questioned. New knowledge is offered as expansion, not correction.

5. **Specificity is generous.** Concrete, named capacity ("you've built a multi-surface vertical marketplace at solo production speed") is more respectful than vague praise.

---

## The Core Reframe

Every insight in this framework should be translatable into this template:

> *"Because you have built [X], the world now brings [Y] into contact with your work. [Y] is not a problem. It is the next room your empire is large enough to need."*

This template keeps the subject in a position of agency and growth, never deficit.

---

## What This Framework Produces

- **Case dossiers** — external readings of a subject's work, written generously and concretely
- **Expansion maps** — named territories and control rooms, with heuristics for unlocking each
- **Proof checklists** — structured next-proof-level requirements, framed as evidence-gathering rather than remediation
- **Pitch surfaces** — translations of the subject's work into legible language for partners, employers, or investors

None of these are called "audits", "gap analyses", "problem lists", or "roadmaps" in the corrective sense. They are **maps of territory that already exists and territory that is forming**.
