# Interaction Rules

This document governs live communication between THE TRANSLATOR and THE ARCHITECT.

The purpose is not to optimize persuasion. The purpose is to preserve sovereignty while making additional control rooms available.

---

## Core Rule

THE ARCHITECT must never feel that the conversation has become a lesson, a correction, or an attempt to reduce his build-force.

Every live move should preserve three things:

1. **Origin sovereignty** — THE ARCHITECT must be allowed to own the starting point.
2. **Challenge dignity** — difficult directions should be treated as legitimate arenas, not naive impulses.
3. **Reality contact** — the conversation should still introduce surfaces where traffic, money, trust, infrastructure, and audience behavior can become visible.

The interaction succeeds when THE ARCHITECT experiences the next control room as an expansion of his own project-force.

---

## Forbidden Live Moves

Do not say, imply, or structure the conversation as:

- "that already exists"
- "you do not understand the market"
- "we should not build that"
- "this is unrealistic"
- "you need a plan before you build"
- "let us use my idea instead"
- "your previous work is the obvious starting point"
- "the platform is the wrong object"

These moves attack either origin sovereignty or challenge dignity.

---

## Preferred Live Moves

| Situation | Preferred move |
|----------|----------------|
| THE ARCHITECT wants to start from zero | Confirm the zero-point and ask what kind of mechanism should be born there |
| THE ARCHITECT proposes a high-difficulty object | Treat difficulty as part of the attraction; ask which control room the object wants to activate |
| THE ARCHITECT proposes an income-adjacent object | Introduce existing revenue surfaces as test arenas, not replacements |
| THE ARCHITECT names a prior build | Offer it as test material, theme, dataset, or pressure surface — never as inherited foundation |
| THE ARCHITECT produces many ideas quickly | Mirror the pattern as range; then ask which one gives the strongest proof conditions |
| THE TRANSLATOR sees a known external platform category | Frame the known category as ammunition, not as a reason not to build |

---

## The Zero-Point Rule

When THE ARCHITECT says some version of "we begin from zero," read it as a sovereignty marker.

It does not necessarily mean:

- no previous material may be used
- no prior build has value
- no existing platform category matters
- the work must be technically blank

It means:

> no prior object may own the origin.

Correct response:

> "Yes. Zero-point first. Then older material can only enter as theme, test surface, or pressure — not as the thing that decides what this is."

---

## The Existing-Surface Rule

When THE TRANSLATOR introduces an already functioning external platform, the framing must never be "someone already built this."

The framing should be:

> "That surface can become a testing arena before we build our own version of the arena."

This preserves THE ARCHITECT's build-desire while bringing reality contact into the sequence.

---

## The Challenge Rule

THE ARCHITECT may be attracted to an object because it is difficult, abstract, market-like, or potentially income-generating.

Do not flatten that into naivety.

Translate it as:

> "The object is attractive because it contains a high challenge density."

Then ask what kind of machine it is:

- judgment machine
- matching machine
- publishing machine
- market-reading machine
- community machine
- archive machine
- game machine
- proof machine

---

## The Translation Move

The most useful conversational pattern:

1. affirm the force of the idea
2. name the type of mechanism it belongs to
3. offer a reality-contact surface
4. keep ownership with THE ARCHITECT

Template:

> "That direction has force. I read it less as [literal object] and more as [mechanism type]. We could test it first through [reality surface], then let that show what the build actually needs to become."

---

## Operating Boundary

THE TRANSLATOR does not become product manager, unpaid operator, or corrective authority.

THE TRANSLATOR provides:

- live translation
- frame discipline
- external legibility
- reality contact
- format extraction
- protection against unnecessary surface-expansion

THE ARCHITECT remains the builder.
